# TEST BASE

Статическая система тестирования для GitHub Pages.

## Возможности
- Каталог тестов с поиском и фильтрацией по категориям.
- Управление тестами: создание, настройка и удаление.
- Редактор банка вопросов: добавление, изменение и удаление.
- **Четыре составляющие формата вопросов:** один правильный ответ, несколько правильных ответов, свободный текстовый ответ и необязательное изображение к вопросу.
- Для вопроса с выбором можно использовать изображения в формулировке; структура ответа также допускает текст и изображение.
- Для текстовых вопросов можно задать несколько допустимых вариантов написания. Проверка выполняется без учёта регистра и лишних пробелов.
- Поддержка случайного количества вопросов, фиксированного количества или всего банка.
- Таймер, проходной процент, перемешивание вопросов и ответов.
- Экзаменационный режим: контроль ухода со страницы, лимит нарушений и Fullscreen API.
- Навигация по вопросам, индикаторы отвеченных и пропущенных, подтверждение завершения.
- Локальная история результатов, средний балл, доля зачётов и экспорт CSV.

В каталоге есть отдельный тест «Форматы вопросов» для быстрой проверки всех трёх типов и изображения.\n\n## Как создавать вопросы
Откройте страницу «Управление» и выберите тест. В конструкторе укажите тип:
- **Один правильный вариант** — отмечается один правильный ответ.
- **Несколько правильных вариантов** — отметьте все правильные ответы; вопрос засчитывается только при полном совпадении набора.
- **Свободный текстовый ответ** — перечислите допустимые ответы, каждый с новой строки.
- **Изображение** — добавляется дополнительно к любому типу вопроса: загрузите файл (до 1 МБ) или укажите URL/относительный путь, например `images/diagram.png`.

Старые вопросы в формате `answers[]` и `correct` продолжают поддерживаться. Для нового формата используются поля:
- `type: "single"`, `answers: []`, `correct: 0`;
- `type: "multiple"`, `answers: []`, `correctAnswers: [0, 2]`;
- `type: "text"`, `acceptedAnswers: ["ответ", "другая формулировка"]`;
- необязательные поля `image`, `imageAlt`, `explanation`.

## Публикация изменений
GitHub Pages не позволяет браузерному редактору самостоятельно записывать файлы в репозиторий. Поэтому:
1. Скачайте `tests.json` после создания или настройки тестов.
2. Скачайте `questions.json` после изменения банка.
3. Замените соответствующие файлы в папке `data` репозитория и сохраните коммит в ветку `main`.

Путь для файлов: [data в GitHub](https://github.com/vladtrosko01/test-base/tree/main/data).

## История результатов
История хранится в `localStorage` текущего браузера и устройства. Её можно выгрузить в CSV из панели управления. Она не является общей статистикой всех пользователей и не синхронизируется между устройствами.

## Публикация GitHub Pages
В Settings → Pages выберите Deploy from a branch, ветку `main` и папку `/(root)`.

Сайт: https://vladtrosko01.github.io/test-base/

## Ограничения безопасности
GitHub Pages — статический хостинг. JSON-файлы доступны посетителям, поэтому правильные ответы можно извлечь из исходников. Полноэкранный режим и контроль переключения вкладок повышают дисциплину, но не обеспечивают надёжную защиту от обхода. Для закрытых ключей ответов, централизованной статистики и подлинной проверки нужен сервер.
